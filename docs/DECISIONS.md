# 技术决策记录

只记录对后续开发有影响的决定，待定项不视为已采用。

## D001 客户端定位（已确定）

- 决策：使用 Flutter 构建 Android/iOS 客户端，优先适配 LXServer 原生 API。
- 理由：以完整服务端能力与移动端体验为核心。
- 影响：不以 Subsonic 兼容接口作为主要数据模型。

## D002 开发与验证顺序（已确定）

- 决策：使用现有 IDEA 环境，先验证 Android 播放闭环，同时保持平台边界。
- 理由：当前开发环境是 Windows，尽快得到真实运行反馈。
- 影响：iOS 功能最终必须在 macOS/Xcode 和真机验证。

## D003 第一版产品与实现（已确定）

- 决策：用户自填服务器地址并登录普通账号；后台、注册和服务端配置留在网页端。
- 设计：沿用白绿视觉，移动端以搜索、简洁歌曲行、迷你播放器和独立播放页组织。
- 状态：Flutter 自带 ChangeNotifier，暂不引入额外状态框架；页面通过控制器调用服务。
- HTTP：http 1.6.0，统一请求、40 秒超时、错误映射，拒绝自动重定向携带凭据。
- 播放：just_audio 0.10.6，提供 Android/iOS 音频能力；本轮先做前台播放，后台服务另行接入。
- 存储：flutter_secure_storage 11.2.0，保存 Token 会话，密码不落盘；启动通过服务端验证 Token。
- 版本：Flutter 3.47.9 / Dart 3.13.7；Android/iOS 平台工程均生成，应用标识为开发占位值。
- 依据：上游 commit 13865b82b19fe51219e3e21948c104a50e6fcebc 的原生路由；依赖以 pubspec.lock 为准。
- 代价：目前无后台通知与播放恢复，无歌词和同步；与用户实际部署版本的兼容性待联调。

## D004 聚合搜索与只读音乐库（已确定）

- 决策：以普通用户可读取的自定义源列表判断就绪解析源和支持平台；失败时保守保留平台，绝不以一次搜索失败判定禁用。
- 聚合：客户端分平台独立分页，部分成功即展示，重试不跳页；同名跨平台条目保留来源。
- 音乐库：读取个人歌单、收藏歌手/专辑和在线歌单，支持自建歌单重命名/删除与关联歌单显式刷新；实时同步另行设计。
- 歌词：独立 LRC 模型，随播放进度高亮；使用请求版本号阻止旧歌词回写，失败不阻止播放。
- UI：搜索 / 歌单 / 我的导航，共享播放服务；客户端保留登录与退出，后台配置仍在网页端。
- 测试：夹具包使用 .integration 后缀，测试命令关闭自动卸载，避免测试清理错误移除普通客户端。

## D005 音质选择与滑页播放器（已确定）

- 默认客户端偏好从固定 128k 改为 flac；初始音质选择规则已由 D006 修订。
- 将请求音质和服务器返回 type 分开保存，缺失返回信息时不显示假无损标记。
- 音质切换保留进度和暂停状态；解析失败继续旧音频，加载失败尝试恢复旧 URL。
- 偏好仅存本机，由控制器通过存储回调保存，不写入服务器用户设置。
- 封面/歌词以 PageView 横向切换，统一控制区；取消歌词弹层和顶部歌词图标，内部歌词滚动不驱动外层分页。
- 模拟器验证使用带质量字段的静音 WAV 夹具，不替代真实音源编码与输出能力验证。

## D006 紧凑浏览与音质请求修正（已确认）

- 搜索/歌单顶部使用紧凑搜索框，移除重复品牌、大标题和文案；筛选与内容共同滚动。
- 旧歌单仅标注 128k 不代表解析源只能提供标准音质，默认偏好 flac；自动候选策略与重播缓存已由 D007 修订。
- 用户选择立即保存；已识别返回音质不符时拒绝该次资源。解析/加载失败后同平台按较低档位重试，成功明确提示降级，首选偏好不变；不跨平台换歌，鉴权失败立即停止。
- 单元/组件测试覆盖 150 首长列表和稀疏音质元数据；模拟器夹具验证请求与错误流程，真实音源能力仍待实测。

## D007 根据歌曲音质选择与短期播放缓存（缓存恢复策略已由 D008 修订）

- 新搜索返回的具体音质列表约束自动候选档位；旧收藏信息完整性未知，继续允许尝试。手动选择和重新尝试首选绕过元数据限制。
- 成功档位 6 小时、失败 2 分钟，经已有安全存储保存；签名 URL 仅在内存缓存 5 分钟，失效先重解析同档位。无需新增依赖，不实现音频文件缓存。
- 隔离服务器、账号、平台歌曲与源配置；退出清空，源列表配置变更失效。成功记录 sourceId，失败仅代表当时该配置下全部解析尝试的结果。
- 降级过程只展示尝试状态；播放器加载错误交给降级循环，全部失败再报告。

## D008 服务端文件优先与同档位换解析源（播放档位记忆策略由 D009 修订）

- 同一目标档位按服务端已有文件、有效内存链接、在线解析顺序加载；缓存查询严格匹配音质、排除名称碰撞，仅接受同源缓存文件。无缓存接口的旧服务端可继续在线播放。
- 新 URL 加载失败先按 sourceId/sourceName 排除失败解析源，服务端声明还有源时同档重试，再按允许档位降级。最多 4 次解析，30 秒调度预算，单个解析请求 10 秒；不硬取消音频解码过程。
- 成功历史不再压过当前首选。失败仅内存短退避 30 秒，不落盘；网络、认证、权限、平台无源直接停止，不当作歌曲音质缺失。
- 此处手动选档即首选的行为已被 D013 替代：仅个人中心修改全局首选，当前歌曲切换仅本次生效。未知有效期 URL 仍采用 5 分钟内存保守上限，后续有可靠有效期字段再接入。
- 暂不触发服务端下载/升级，也未实现手机音频字节缓存。源码审查及当前覆盖范围见 CACHE_REVIEW.md。

## D009 长期沿用歌曲成功档位与版本追踪（已实现）

- R010：全局首选负责新歌曲首次选择；每首歌曲成功档位绑定该首选后长期保存，无 6 小时到期探测。URL 仍短期失效，过期仅获取同档地址。
- 原档失败后重新选档；手动修改首选清除旧记录，主动重试清除当前歌曲记录。保留账号/服务器/源配置隔离与清理；最多 200 条最近成功播放记录，容量淘汰另行定义，不伪装成永久无限历史。
- 新字段 preference 缺失的历史记录不猜测关联，成功后建立新记录。自动降级不改全局首选。
- R013：上游基线固定 v2.2.0 与精确 commit；COMPATIBILITY 区分源码依据、适配和部署实测，REQUIREMENTS 记录需求及验收，CHANGELOG 按客户端版本归纳，不复制聊天记录。
- 此处是客户端产品策略，不宣称 LXServer 网页端也采用相同长期档位记忆。

## D010 音质选项分组与服务器文件徽标（已实现）

- R008：具体歌曲标注、当前解析标注及服务器已有文件音质放主列表；其余未知档位折叠为“尝试其他音质”，可信完整列表明确缺失的档位不显示。失败一次不作为永久不支持证据，首选不因分组变化而修改。
- R017：参照 v2.2.0 server_file_state.js，一次读取 /api/music/cache/list 建索引、60 秒复用和并发合并，不逐首探测；按用户会话隔离，退出清除，读取失败不展示假状态。
- “已缓存/已下载”均为 LXServer 管理的存储，tooltip 列出音质及服务器位置，不代表手机音频文件。普通字号保持两行，大字/极窄屏允许标签换行。
- 平台、音质和文件状态色依据 app.js getSourceTag/getQualityTags、theme_variables.css .t-badge-*；统一 MusicBadge，避免页面各自编造颜色。

## D011 手机缓存与下载分开管理

状态：已确定。替代 D010 中列表展示服务端文件状态的决定，保留其平台/音质配色。自动缓存容量上限与 LRU、下载独立保留；文件和会话隔离。新增直接依赖 path_provider 获取私有目录、crypto 生成稳定文件标识，二者原已存在于传递依赖中。LocalMediaController 管理索引、文件和串行队列，AudioTransfer 通过本机代理向播放器提供普通 URL。详细生命周期、参考资料及限制见 [LOCAL_MEDIA.md](LOCAL_MEDIA.md)。

## D012 播放页模式与评论

状态：已确定。模式参考固定上游 `public/music/app.js` 的 nextIndex 分支：order 末尾停止、list 回到首曲、single 自动完成后重复、random 多曲时排除当前曲。客户端单曲循环下手动下一首仍切到下一首，上一首在随机模式下另选非当前曲；不宣称无重复洗牌。选择作为客户端偏好持久保存，默认顺序播放，不改变服务端配置。

评论只调用歌曲原平台的原生只读接口，不实现账号对第三方平台的发表、点赞。面板绑定打开时歌曲快照，避免后台换歌后评论身份混淆。信息标签和歌曲操作由列表/播放页共用组件；当前布局将音质入口置于播放页更多菜单，标签只读，列表菜单不提供音质，评论紧邻下一首。

## D013 分离全局首选与临时音质

状态：已确定，替代 D008 的手动切换自动保存全局首选行为。个人中心修改首选并持久保存，用于后续播放，当前音频不立即重载；当前歌曲通过播放页更多菜单中的“音质选择”切换，保留进度和暂停状态，不调用偏好保存，不修改长期成功档位记录。重新尝试首选仍可清理当前歌曲旧记录并建立新的成功档位。临时切换使用同一套解析/降级策略，但不写结果记忆；完整本机文件仍可被复用。下载单独选档，遵循歌曲已知/未知音质分组。

播放页只显示当前确认音质；列表显示歌曲最高标注音质。二者共用标签样式、平台和本机状态，不将标注最高档误认为正在播放档位。顺序播放用同向双箭头，评论用圆角双气泡图标，无新增依赖或服务端契约。

## D015 本机缓存优先淘汰未采用版本（已被 D016 替代）

状态：已替代，当前采用 D016 的普通 LRU。原方案容量不足时先淘汰同平台同首歌未采用的其他音质，再按最近实际使用时间；当前播放占用和主动下载受保护。已采用版本必须有完整文件，才将其他版本标记冗余，避免所选版本不可用时提前丢弃唯一离线副本。存储保留记录与音质播放默认值、长期成功档位分开，跨启动保存；详细流程、来源、边界和测试统一见 [PLAYBACK_ENGINE.md](PLAYBACK_ENGINE.md)。不按固定天数清除本机音频，不按标题跨平台去重。

下载封面曾因 _songData 白名单遗漏 img 而在重启后丢失。现保存安全封面 URL 和本机封面；旧数据按同平台歌曲 ID 补齐，拒绝按标题猜测。细节与验证见 PLAYBACK_ENGINE.md。

## D017 冷启动恢复界面，显式点击后继续播放

状态：已确定。保存队列、当前位置和音质，启动时恢复为暂停，避免启动即发声或解析音频。源地址不持久保存，继续时重新走正常本机/服务器/解析策略。普通进度每 3 秒合并保存，暂停/切歌/后台补存；最多保存包含当前歌曲的 2000 首窗口。细节与边界集中在 PLAYBACK_ENGINE.md。

## 歌单浏览与写入

采用 [用户已确认的原型](design/playlist-detail-prototype.png)。详情按封面信息区、独立播放工具栏和歌曲列表组织，替代此前封面/计数/播放/搜索挤在同一行的布局。信息区随内容滚动，收起后导航显示可滚动标题；播放工具栏滚到导航下方后吸附，编辑时全选/完成栏沿用吸附；搜索按需展开并暂时隐藏信息区，取消恢复首页。信息区采用从导航背景向白色列表的纵向浅渐变，减少分区色差与底部留白。默认白绿配色，来源没有创作者、简介、播放量或日期时自然缩短，不虚构字段或展示空占位。日期只保留上游 time 的含义，不统一称为更新时间；收藏跳转先匹配同平台及原 ID 的已有列表摘要，避免丢失已有日期；详情未返回且无缓存时保持缺省，不新增搜索请求。私人歌单没有标准 createTime，不用当前时间、收藏时间或 locationUpdateTime 冒充创建时间。

分页为本机偏好，默认连续、每页 20 首，可选 10/20/30/50/100；仅影响展示，播放队列仍为所有已加载歌曲。歌曲行保留封面与原标签。多选跨页保留，操作只作用于已选歌曲，支持下一首播放、收藏到私人歌单、复用本机下载模块及删除，不增加框架或依赖。编辑隐藏迷你播放器，圆形选择位于封面前，右侧拖动柄仅用于排序。私人歌曲排序为本页草稿，完成才保存，返回可保存/放弃；删除确认后将待保存顺序一起提交。外部原歌单不支持写入，用户编辑的是私人副本。

收藏、重命名、删除、显式刷新依据 v2.2.0 的全量 POST 契约：用户确认，完整拉取来源，再重读私人快照后修改目标并写回；收藏保存 source/sourceListId/Album/locationUpdateTime，使用随机 ID 和原生 LX 歌曲 id/meta 格式，保留其他列表与未知字段。重复收藏在最新快照中查重；分页错误不提交部分歌单。保存及重读完成前保持客户端写入锁，切账号/销毁使旧操作失效；不自动重试写请求。服务端没有 CAS，仍无法保证其他设备并发编辑无冲突。来源新图缺失时保留原封面，详情监听歌单重载更新。歌单列表右侧常显拖动柄，长按行打开原操作面板，详情页菜单保留；全部歌单松手保存顺序，系统项同样参与排序。沿用网页 favoriteSidebarOrder 表达包含系统项的显示顺序并保存到账号设置；私人歌单相对次序仍写回 userList。保留其他账号设置与网页隐藏入口，不更改网页 saveAccountSettingsToFile 开关；网页加载服务端设置仍受自己的同步开关控制，不宣称跨端实时一致。两个接口没有事务，部分保存失败明确提示，拒绝自动回滚已确认写入。

## 平台选择与简单歌单聚合

搜索与歌单页移除显式“全部”，点击已选平台即可取消，未选代表聚合。两个页面共用等宽铺满的平台行（网易/QQ/酷狗/酷我/咪咕），收藏三个分类同样等分；首次默认网易，保留已有选择，大字体放不下时等宽横滑；去掉额外底部 padding 并移除右侧状态/刷新按钮，依靠下拉刷新；每页选择独立记忆，仅保存稳定平台 ID，记录损坏/未知标识回网易，已禁用平台选择回聚合，不增加偏好同步、标签数量协议或分类映射。歌单聚合由客户端并发读取单平台原生接口，按平台交错合并且独立翻页；只混合推荐/搜索，平台特有分类与排序仅单选时展示。推荐以平台返回的首个排序为默认，短期复用；不将各平台推荐排序解释为统一热度排名。

## 列表分页与统一弹框

依据已确认的 [交互原型](design/browse-pagination-prototype.html) 与 [预览图](design/browse-pagination-prototype.png)：聚合始终连续；单平台沿用个人中心模式，启用分页时使用原平台 total 计算页数。未知总数仅显示当前页，不再显示缓存分母或“还有更多”。分页栏统一 32px，与紧凑播放器无额外上下间隔，附“跳页”入口；输入/滚轮确认后跳转，取消不改变位置。单平台按原生页缓存读取目标窗口，避免为远页下载此前所有内容。页码是平台报告范围，空页/重复页保留原位置并提示。

弹框统一视觉规则，不统一固定高度：选择、信息及输入采用白色圆角底部面板，标题 18、说明 12–14、选中态浅绿、确认按钮 42；键盘和安全区由公共容器处理。删除、清除、退出使用紧凑确认框及警示色，保留显式确认。即时应用的音质面板标为“关闭”，需要确认的选择标为“取消”；下载音质选择后仍须点击底部下载按钮。所有旧 showDialog/showModalBottomSheet 调用迁入公共封装，排序/设置下拉与菜单统一白底圆角。不增加依赖，不改变鉴权、写入或播放策略。

## D022 系统媒体服务复用统一播放控制器

采用 audio_service 0.18.19 和 audio_session 0.2.4（由传递依赖提升为直接依赖）接入后台媒体服务、锁屏及通知栏控制。现有播放器每首按音质/本机缓存策略单独加载，自定义 AudioHandler 将上下首交回业务队列，避免简单后台包装下的队列协调问题；实例与队列继续由 PlayerController 唯一持有。暂停保留 Android 前台服务以便锁屏恢复，系统停止/移除任务清空队列并取消在途解析。元数据仅在实际播放后激活，冷启动恢复不抢占系统媒体会话。平台配置与验收边界见 PLAYBACK_ENGINE.md。
