# 播放内核机制与优化

本文件统一维护当前机制、边界和验证，后续内核调整更新对应章节，不另建逐轮聊天记录。需求状态见 REQUIREMENTS，长期取舍见 DECISIONS。

## 证据与版本

- LXServer v2.2.0，commit `13865b82b19fe51219e3e21948c104a50e6fcebc`；基线脚本已核对，不代表用户部署 commit 已确认。
- 调用与字段依据：`src/server/server.ts` 的解析、歌词、缓存查询分支；`src/server/music/fileCache.ts`、`cacheCleanup.ts`；网页 `public/music/app.js`。
- 服务端清理支持容量及配置保留期，按文件最近访问/修改时间排序，保护使用中资源；超限回收目标可达配额的 95%。这些是服务端策略，客户端不会冒充或修改它们。

## 播放与音质

统一 PlayerController 管理音频、队列、歌词与异步代际。页面只发操作；旧请求不能替换新歌曲。

歌词通过带当前用户鉴权的 `GET /api/music/lyric` 获取，携带歌曲平台、ID、名称及平台专用字段，由 LXServer 优先读取已有歌词并处理在线失败后的内嵌歌词回退。客户端不直接请求 QQ，也不因歌词失败中断音频。GET/POST 差异与真实部署证据见 API.md。

1. 新歌曲按默认音质与可信音质元数据选档；已有成功档位沿用记录。元数据不完整时允许尝试，未知选项在面板折叠。
2. 普通播放先查本机完整文件，再查同档服务器文件、有效地址、同平台解析源；手动选档按选择档位顺序查询，不先跳到较低本机版本。
3. 同档失败先排除已失败解析源再尝试其他同平台源，随后才降级，不自动跨平台换歌。最多 4 次解析请求，恢复调度预算 30 秒；已发请求另有网络超时，预算不是所有网络请求的硬取消时限。
4. 默认音质由个人中心保存；当前歌曲切换不修改默认值或长期成功档位。重新尝试默认音质是显式重新探测入口。
5. 自动完成遵循顺序、列表循环、单曲循环、随机模式。后台服务、锁屏控制尚未实现。

## 退出后恢复播放状态

播放器私有 `lx_playback.json` 保存当前队列、索引、进度、时长和请求/已确认音质；歌曲使用与下载相同的最小字段白名单，不保存播放地址、Token 或密码。模式、默认音质沿用各自偏好存储。

重新打开且同服务器同账号会话恢复成功后，只还原界面和进度，保持暂停，不创建音频流。点击播放才按已有本机文件/解析策略加载，带着保存的进度继续；暂停恢复界面也可先拖动进度。服务器网络不可达时同样可还原已保存状态，本机资源仍可播放。

播放中约每 3 秒合并保存一次，暂停、切歌、队列数量改变以及 App 进入非活跃/后台时立即补存；只在写入时序列化队列，不随每次进度回调反复编码。写入用临时文件原子替换且串行执行，快速回退进度也保留最后操作。强制结束进程无法保证最后回调，最多可能损失最近一次定期保存后的进度；不是后台播放服务。

队列最多保存包含当前歌曲的 2000 首窗口；超大队列外围歌曲不会全部恢复。损坏、未知版本、其他账号/服务器的记录忽略。清空队列、主动退出或确认登录失效时清除恢复记录，避免回到已经清掉的队列。

源码参考固定上游 `public/music/app.js` 的 savePlaybackState/restorePlaybackState；该网页保存 song/index/time/playlist/quality 等，网页队列上限为 300。本客户端使用应用私有文件和 2000 首窗口，属于客户端设计，不改变服务端契约。`playback_resume_test.dart` 覆盖保存/重启、隔离、敏感字段过滤、快速回退、清空顺序、损坏数据和离线恢复；实际解码继续播放由 Android 夹具验证。

## 四类记录不能混用

| 记录 | 当前规则 |
| --- | --- |
| 成功/失败音质 | 成功档位按服务器、账号、源配置与默认值关联，最多 200 条；不因过了 6 小时重新试高档。失败只在内存退避 30 秒 |
| 播放地址 | 内存最多复用 5 分钟；失效重新解析，不持久保存签名 URL |
| 本机音频缓存 | 完整、解码加载已接受的文件才登记；默认全机应用缓存上限 512 MB，可关闭或设置 256 MB / 1 GB / 2 GB；不按固定天数自动过期 |
| 主动下载 | 独立文件，不受缓存容量淘汰与清缓存影响；卸载应用会删除私有文件 |

## 本机缓存身份与去重

文件标识为服务器、账号、平台歌曲 ID、请求音质的散列。不同解析源返回同一平台歌曲同一音质时不另外建立多个逻辑副本；不同音质可共存。不同平台歌曲不按名称猜测相同，也不自动合并 Live、翻唱等版本。

播放器成功采用资源后才刷新该文件的使用时间；查询文件、尝试失败不会刷新。所有音质版本按相同 LRU 规则处理，不把最近一次选档当作长期偏好。旧索引的 `retainedQuality` 不再读取，下一次保存自动移除。

## 容量不足时的淘汰顺序

保护当前播放使用的文件，排除全部下载文件，然后执行：

1. 按最近实际使用时间从旧到新淘汰，不按最初加入时间，也不为未选中音质增加淘汰优先级。空间够用即停止。
2. 预留新缓存空间时同样遵守保护与 LRU；保护中的文件导致容量不足时，新流跳过自动缓存并正常在线播放。未知长度或单文件超过上限也跳过自动缓存。

缩容或清空遇到播放占用时，允许暂时超限，释放后补清理。简化理由：暂时选择某音质不代表放弃其他音质，额外优先级目前收益不足以抵消复杂度。

## 清除与文件生命周期

- 点击“已缓存”可确认清除此歌曲缓存；存储面板可按音质清理。只操作当前账号的本机缓存，不删除下载、其他歌曲或 LXServer 文件。
- 正在播放的文件标记“切歌后清除”，释放后删除；当前传输不会重新把被清除文件登记回来。
- 下载复用同档缓存或正在进行的缓存传输；成功转为下载后删除重复缓存，播放占用时延迟释放。重新下载成功才替换旧文件。
- 私有临时文件传输完成后校验、原子改名。启动清理遗留临时文件；文件丢失或大小不符的索引不用于播放。
- 退出保留本机文件但按账号隐藏。缓存上限覆盖应用全部账号的普通缓存；文件访问仍按服务器与账号隔离。

## 传输与限制

AudioTransfer 共享一次网络传输给磁盘和回环范围代理，播放器读取普通 URL；第三方音频请求不添加 LXServer 登录凭据。完整文件可离线播放；下载封面成功保存后可离线显示，离线歌词尚未实现。

## 下载封面与元数据

下载索引持久化标准化封面地址及来源平台；含敏感鉴权参数的封面 URL 不写索引。下载完成后通过独立串行任务异步保存封面到应用私有 artwork 目录，按服务器、账号、平台歌曲 ID 共用，单张最大 2 MiB，失败不影响音频下载。列表、迷你播放器及播放页优先用本机封面，缺失时尝试网络地址。

旧记录如果已丢失图片地址，不能离线猜回。刷新歌单或搜索获得同平台、同歌曲 ID 的元数据时补齐，再保存封面；不按歌名匹配。删除最后一个对应下载会删除其封面；启动清理孤立封面与临时文件。下载封面随下载管理，不占自动音频缓存配额。

下载队列当前为前台串行任务。暂停或进程重启后可以继续任务，但当前文件从头下载，未实现字节断点续传与后台下载服务。首次登录需要网络；已有安全会话只有验证遇到网络错误才允许离线恢复，鉴权拒绝仍清除会话。
